Configs: an experiment is a YAML file

Two "seams" make experiments cheap Seam 1, encoding (encoding.scheme): note_chord, interval, pitch_duration, event.
Seam 2, architecture (model.arch): lstm or transformer.
Every other module works with any combination, so comparing them is a one-line config change.
The model went through five versions v1 ran on a CPU (2×256 LSTM, 100-token context, ±3 keys). v2–v5 ran on an RTX 5070 GPU. v5 is the final model: 3×512 LSTM, 256-token context, ±6 keys, adaptive softmax. Training time fell from about 8 hours to 11 minutes.

Person 2

Reading MIDI and snapping it to a grid

src/data/parse.py · src/data/types.py

A MIDI file is a list of notes with start and end times in seconds. Before a neural network can learn from it, we turn each file into a clean, regular Piece.

The two data types everything else uses (types.py)

NoteEventpitch (MIDI number, middle C = 60), start and duration in beats, velocity (loudness).
PieceA list of NoteEvents sorted by time, plus style (Classical / Jazz / Blues, taken from the folder name) and tempo.

Quantization: snapping to a 16th-note grid

What _parse_file() does to each file, in order

  1. Read it with pretty_midi and check the time signature. A piece is kept only if every signature it uses is 4/4, 3/4 or 2/4.
  2. Collect notes (_collect_notes). track_strategy: merge joins all non-drum tracks into one stream. That is safe because every ADL track is a piano.
  3. Convert seconds to beats. With tempo_map: true, _beat_mapper follows every tempo change. 16% of files change tempo; using only the first tempo pushed 263 of them off the beat, the worst by more than 600 beats.
  4. Quantize start and duration to the 0.25-beat grid with quantize().
  5. Filter: drop notes shorter than min_duration and pieces with fewer than min_events notes.
  6. Merge duplicate notes (_merge_duplicate_onsets): the same pitch twice at one moment used to create fake chords like 60.60.
  7. Label the style from the folder name (_style_from_path).

load_corpus() runs this across all files in parallel worker processes.

The numbers at this stage The ADL Piano MIDI dataset has 11,073 files in 18 genre folders. The three chosen genres hold 2,019 files (Classical 1,398, Jazz 492, Blues 129). After the time-signature and length filters, 1,654 pieces (1.88 million notes) remain.

"Parsing turns messy human performances into tidy notes on a 16th-note grid, measured in beats rather than seconds."

Person 2

Splitting and augmenting, in the right order

src/data/augment.py

This page covers the most important correctness rule in the project: split first, augment second.

split_pieces(pieces, cfg)

  • Shuffles piece indices with a fixed seed (split_seed: 1337), so every run gets the same split and a checkpoint can always be re-evaluated on the exact data it was tested on.
  • Takes 10% for validation, 10% for test, and the rest for training.
  • Removes duplicates: ADL contains some pieces twice under different file names. Any validation or test piece whose notes match a training piece, even in another key, is dropped. That is why the final split is 1,324 / 162 / 161 rather than 1,324 / 165 / 165.

transpose_augment(pieces, cfg)

  • Keeps every original and adds a copy shifted by each offset in transpose_range (v1 used ±3, so 7 keys; v3 onward use ±6, so 13 keys).
  • A copy is dropped whole if any note would leave the piano range 21–108. Clamping single notes instead would distort the melody's shape.
  • Why transpose at all? A melody means the same thing in any key. Showing it in all 12 keys teaches the model musical patterns, not "this tune is in C".
Honest result worth mentioningGoing from ±3 to ±6 did not measurably improve validation loss (3.710 vs 3.714). It was kept because it covers every key, but it is a negative result, not a win.

"We split by piece before augmenting and we remove duplicate songs, so our validation score measures real generalisation."

Person 3

Turning music into tokens

src/data/encode.py

A neural network cannot read notes; it reads integers. The encoder turns a Piece into a list of text symbols, and the vocabulary later turns each symbol into a number. This is "seam 1": the encoding scheme can be swapped in the config.

The note_chord encoder used by the final model

Two decisions that shaped the vocabulary

DecisionWhy
Run-length rests
<REST:k>		With one <REST> per silent step, 56% of all tokens were rests, and 75% of generated tokens. The model spent its capacity predicting silence. Run-length rests cut that to 36% and made sequences 26% shorter.
No duration in the symbol
include_duration: false		Writing the length into the symbol (60.64.67_1.000) multiplies every chord by every possible length. On the same data the vocabulary was 363,455 symbols with durations and 17,886 without. Note length is rebuilt at playback time instead (Person 5).

The other encoders (seam 1)

SchemeSymbols look likeVocabularyResult
note_chord (used)60, 60.64.6737,020Final model. In-key 0.884
interval+2, -5~400"Differential music". Drifts out of key
pitch_durationP60, D1.000smallMelody only, no chords
eventT2 N60 D4184Exact durations, no <UNK>, but in-key fell to 0.61

Every encoder has a decode() that reverses encode(). Tests check that decode(encode(piece)) gives back the same music.

Person 3

Vocabulary, windows and teacher forcing

src/data/vocab.py · src/data/dataset.py

The vocabulary (Vocab.build)

  • Maps each symbol to an integer id. Reserved ids come first: <PAD>=0, <UNK>=1, <BOS>=2, <EOS>=3, <REST>=4.
  • Built from the training split only. Including validation or test symbols would leak information about them.
  • Ids are assigned in sorted() order. Python set order changes between runs, and a reloaded model would then decode every token as the wrong note.
  • Pruning: min_freq: 10. 60% of raw symbols appear only once and can never be learned, yet each costs an embedding row and an output column. Symbols seen fewer than 10 times are mapped to <UNK>; that affects about 4% of tokens. Rest and style tokens are never pruned, because losing a rest shifts every later note in time.
  • Saved as vocab.json next to the trained model, so the model can never be paired with the wrong vocabulary.

Cutting sequences into training windows (MusicDataset)

Why teacher forcing matters

Scoring only the last position of each window threw away 99% of the work the network had already done. Scoring every position raised the training targets per epoch from 623,000 to 10.3 million for the same compute.

During training the model is always fed the true previous tokens, not its own guesses.

The processed cache

prepare_data.py saves token ids as .npy files in data/processed/<hash>/, plus vocab.json and meta.json. Final cache: 12.8 million training tokens, vocabulary 37,020.

make_dataloaders() shuffles training windows each epoch and serves them in batches of 48.

"Every chord becomes a word in a 37,020-word vocabulary, and we train on 256-token windows where every position is a prediction target."

Person 4

Inside the LSTM model

src/models/lstm.py · src/models/__init__.py

MusicLSTM takes a batch of token ids [B, 256] and returns a probability for every vocabulary symbol at every position [B, 256, 37,020]. Position t predicts token t+1.

Why an LSTM and not a plain RNN?

A plain RNN multiplies its memory by the same matrix at every step, so old information fades (vanishing gradients). An LSTM keeps a separate cell state c that is changed only by adding and gating, so a motif from many steps ago can still matter.

Details in _init_weights()

  • Orthogonal recurrent weights, so repeated multiplication over 256 steps neither explodes nor vanishes.
  • Forget-gate bias = 1, so the cell starts out remembering and learns when to forget.
Adaptive softmax (model.output: adaptive) A normal output layer scores all 37,020 symbols at every position, which was the slowest and most memory-hungry part. Adaptive softmax scores the 2,000 most common symbols (89% of targets) at full size and the rare ones in smaller groups. The probabilities are still exact. Measured: 41% faster per batch, GPU memory 5.9 GB → 1.2 GB, and a better validation loss.

Seam 2: transformer.py has the same interface (8-head causal self-attention). It is built and tested on the demo data only; it has not been trained on the full corpus.

How the model is trained

src/train.py

Key settings (v5)

SettingValue
LossCross-entropy, <PAD> ignored
OptimizerAdam, learning rate 0.001
Gradient clipping5.0
Batch / context48 windows × 256 tokens
LR scheduleplateau: halve LR when val stops improving
Early stoppingpatience: 3
HardwareRTX 5070 GPU, ~106 s per epoch

Safety features

  • Atomic checkpoints: written to a temp file, then renamed, so a crash cannot corrupt best.pt.
  • Resume (train.resume: true) restores weights and Adam's state.
  • Config hash check: a checkpoint refuses to load against data built with different settings.
  • VRAM warning: on Windows a full GPU silently spills to system RAM and epochs become 20× slower.
  • history.csv logs every epoch.

Validation loss by epoch (real data)

From runs/adl_mixed_lstm*/history.csv. v5 overfits after epoch 3: training loss keeps falling (2.86) while validation rises, so early stopping ends the run at epoch 6 and keeps the epoch-3 weights.

Tried and rejected: bf16 mixed precision25% faster, but validation loss after one epoch was 5.35 vs 4.80 in normal precision. Speed alone was not a good enough reason.

"We train with Adam and cross-entropy, keep only the best checkpoint by validation loss, and stop as soon as the model starts to memorise."

Person 5

Generating new music

src/generate.py · src/sampling.py · src/decode.py

Step by step (generate())

  1. Load best.pt and the vocab.json beside it. Refuse to run if the vocabulary does not match the data it was trained on.
  2. Prime with a real excerpt from the validation split. The model never trained on it, so it cannot simply recite a memorised piece. You can also prime from your own MIDI (--seed-midi) or an MP3 via app/transcribe.py.
  3. Sample the next token (sampling.py).
  4. Repeat. Write the tokens as .txt, decode them to notes, write .mid.

Each run prints its random seed, so any sample can be reproduced with --seed N.

Sampling choices (sampling.py)

  • Sample, don't pick the top token. Always taking the most likely token collapses into one note repeated forever.
  • Temperature 0.9: divides scores before softmax. Below 1 is safer, above 1 is more adventurous.
  • top-k / top-p: cut off unlikely tokens. Available but off: it kept the music in key but doubled the repeated-note rate.
  • Banned tokens: <PAD> <BOS> <EOS> <STYLE> <UNK>. <UNK> used to be drawn 4% of the time and became a silent gap.

From tokens to sound (decode.py)

The note_chord model never predicts note length, so fill_durations() rebuilds it at playback time. This is what fixed the "random, staccato" sound, not the vocabulary change. render_audio.py then synthesises a 44.1 kHz stereo WAV with a pure-numpy piano model (decaying partials, reverb, loudness normalisation). The instrument is chosen at render time; the model only decides which notes, not how they sound.

The data-pipeline audit before v4 Three bugs changed what the model trained on: (1) <STYLE> tokens were silently dropped, so v1–v3 never saw a genre label; (2) the same pitch twice at one moment made fake chords like 60.60; (3) duplicate songs leaked from train into validation and test. Piece endings were also never used as targets. All four are fixed and covered by tests/test_data_audit.py.

Known limitations

  • No long-range form. 256 tokens ≈ 93 beats ≈ 23 bars of 4/4. The model cannot bring back a theme from a minute earlier. This is why a Transformer arm exists.
  • Overfits early (after about 3–5 epochs). More varied data would help more than a bigger model.
  • Durations are estimated, not learned, and about 4% of chords are <UNK>.
  • Weak style conditioning: the style token is only at the start of a piece, so most windows never see it.

"The final model keeps 88% of its notes in key, the same level as real music, and it does not copy its training data."

For the whole group

Likely questions, with short answers

What is teacher forcing?

In training the model is given the true previous tokens, not its own guesses. Every position in the window becomes a target, so one 256-token window gives 256 training examples.

Why sample instead of picking the most likely token?

The most likely continuation of a repeated note is usually that note again, so greedy decoding gets stuck repeating one note.

What does perplexity 37 mean?

On average the model is as unsure as if it were choosing between 37 equally likely symbols, out of 37,020. It has narrowed the field about a thousand-fold.

How do you know it isn't copying?

It is primed with validation music it never trained on, and copy_metrics shows the longest verbatim match is about 11 tokens, with less training-set overlap than real unseen music.

Why is the vocabulary so large?

Every distinct combination of simultaneous notes is its own symbol, and real piano music has tens of thousands of different chords.

What is adaptive softmax?

An output layer that scores the 2,000 common symbols in full and the rare ones in smaller groups. Same exact probabilities, 41% faster, a fifth of the memory.

Why is the split done before augmenting?

Otherwise transposed copies of a validation song end up in training, and validation measures memory, not generalisation.

Why an LSTM and not a plain RNN?

Gates and a separate cell state stop the memory from fading, so information from hundreds of steps back can still affect the next note.

What would you do with more time?

Train the Transformer on the full corpus (long-range form is the main weakness), and pair the event encoding with a stronger model so it keeps exact durations and stays in key.

Which metric matters most?

in_key_pct, read together with distinct_n: a model that repeats one safe phrase also scores high on key.

What surprised you?

Data preparation mattered more than the model. Run-length rests, duplicate removal and the tempo fix each changed results more than adding layers did.

Can someone reproduce your results?

Yes. The split seed is fixed, every generation prints its seed, the vocabulary is saved beside the model, and 383 tests check the pipeline.
